# 0009: Correct measurements with an explicit impact review

A 30 ft vessel can have a valid booking on a 75 ft face, then be corrected to 120 ft. Serializing writes protects a booking decision while it happens, but does not protect it from later changes to its inputs. Before a length change, recheck that vessel's active stays and overlapping neighbours with the existing Python rules. A read-only preview returns before/after findings and a fingerprint of the relevant facts. Saving rechecks under the write lock; if blocking findings remain, require a reason and the current fingerprint. A stale acknowledgement returns the new findings instead of saving. Commit the corrected fact and its review together in an additive `vessel_changes` table, retaining affected reservation IDs, findings and reason. This allows truthful corrections without silently approving bookings that no longer fit. The bookings remain visibly flagged until resolved; measurement acknowledgement is distinct from a reservation override. Include historical non-cancelled stays because measurement corrections also change what Harbor can verify in the imported history. This narrowly scoped record is not a complete edit log or user attribution system. The UI also exposes existing reservation edits and annotations, and separates the fixed import audit from the current ledger. No new dependency is needed.
