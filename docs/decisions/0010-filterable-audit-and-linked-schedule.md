# 0010: Personal audit filters and a shared schedule date

The audit needs to answer a coordinator's specific question without changing what the historical workbook proves. Python now exports individual finding evidence, with original names, berth, dates, source references and category. Capacity and unverifiable findings retain one row per berth-day so a date filter has exact boundaries; closure rows use the actual overlap. The website reads this fixed sample audit in both deployment modes and filters it locally by name, berth, inclusive dates and finding type. It never reimplements a rule or drops another vessel from a capacity calculation. Filtered counts explicitly count findings; the unchanged workbook reference is separately labelled. Remembered filters are opt-in, local to the browser, validated on load and removable without an account. Invalid dates keep the last valid results visible with an explanation. Finding links open the current ledger's dates, with the historical/live distinction stated. Grid and Harbor are layouts of one Schedule tab, sharing a day and month; switching layouts preserves the selected day, and changing months clamps it to the month's final day. Side by side stacks on small screens and date headers support keyboard selection. Existing `#grid` and `#harbor` links continue to work; `#split` opens both. No application dependency is added; Node's built-in test runner covers filter semantics alongside the Python evidence tests.
